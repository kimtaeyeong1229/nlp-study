우리는 보통 딥러닝을 공부할 때 이미지 데이터를 우선적으로 배우게 됩니다. 이미지 데이터는 형태 자체가 정수형으로 이루어져 있어, 딥러닝 혹은 머신러닝 모델에 입력할 때 별도의 어려움 없이 입력할 수 있습니다. 하지만 우리가 사용하는 자연어를 생각하면 모델에 어떻게 입력해야 하는지 의문이 생깁니다. `"Hello World!"`를 어떻게 딥러닝 모델에 입력할까요?

이번 글에서는 이 의문에서 출발합니다. 먼저 이미지 데이터와 텍스트 데이터가 무엇이 다른지 짚어보고, 그다음 `"Hello World!"`가 모델이 계산할 수 있는 실수 벡터가 되기까지의 과정을 따라가 보겠습니다.

# 1. 이미지 데이터와의 차이

이미지의 픽셀 값은 연속적입니다. 130과 131 사이에는 130.5가 있고 그 값도 "조금 더 밝다"는 의미를 가집니다. 값을 조금 바꾸면 결과도 조금 바뀌므로 gradient가 자연스럽게 정의됩니다.

텍스트를 숫자로 바꾸면 사정이 다릅니다. GPT-2 토크나이저에서 `Hello`는 15496번, `World`는 2159번인데, **이 번호는 사전의 몇 번째 항목인지를 나타낼 뿐이라 크기를 비교하는 것이 아무 의미가 없습니다.** 사전을 다른 기준으로 정렬하면 번호도 완전히 달라집니다. 애초에 텍스트에는 픽셀처럼 주어진 최소 단위가 없어서, **무엇을 하나의 기호로 볼 것인지부터 우리가 정해야 합니다.** `"Hello World!"`를 `Hello / World / !`로 자를지 `He / llo / Wor / ld / !`로 자를지는 데이터가 아니라 설계자가 결정합니다.

크기를 다루는 방식도 다릅니다. 이미지는 크기가 제각각이어도 리사이즈나 크롭으로 맞출 수 있지만, **문장에는 길이를 줄이는 연산이 없습니다.** 단어를 절반으로 자를 수는 없기 때문입니다. 두 단어짜리 문장과 500단어짜리 문서를 같은 텐서에 담아야 하는데, 이 문제는 뒤에서 패딩으로 해결합니다.

순서가 갖는 의미도 반대입니다. CNN은 고양이가 어디에 있든 고양이로 인식하도록 translation invariance를 얻으려 하지만, 텍스트는 순서가 바뀌면 의미가 바뀝니다. `"Hello World"`와 `"World Hello"`는 같은 단어로 이루어져 있지만 하나만 인사말입니다.

다만 컴퓨터 비전에서 배운 것이 버려지지는 않습니다. Residual connection과 LayerNorm은 Transformer 블록을 이루는 핵심 부품이고, ImageNet 사전학습 후 파인튜닝하는 방식도 뒤에서 볼 사전학습 언어 모델과 같은 발상입니다. **차이는 대부분 입력을 만드는 앞단에 몰려 있습니다.**

# 2. 토큰화

가장 직관적인 방법은 공백으로 자르는 것입니다. 하지만 곧바로 두 가지 문제에 부딪힙니다.

첫째, **학습 때 보지 못한 단어는 전부 `<unk>` 하나로 처리됩니다.** 고유명사, 신조어, 오타가 모두 같은 토큰이 되어 정보가 통째로 사라집니다. 둘째, **어휘가 폭발합니다.** 영어만 해도 활용형까지 포함하면 수십만 개인데, 어휘 크기 V가 커지면 V × d 크기의 임베딩 행렬과 출력층 softmax가 함께 커집니다. V = 200,000에 d = 512면 임베딩만 1억 파라미터입니다.

반대로 글자 단위로 자르면 어휘는 100개 남짓으로 줄고 미등록 단어도 사라집니다. 대신 시퀀스 길이가 5~10배 늘어나는데, Transformer의 attention은 길이의 제곱에 비례하므로 부담이 큽니다. 게다가 토큰 하나에 의미가 없어서 모델이 글자를 단어로 조합하는 것부터 배워야 합니다.

답은 중간에 있습니다. **자주 나오는 단어는 통째로 두고, 드문 단어만 조각으로 쪼개는** 서브워드 방식입니다.

```
"Hello"        → ["Hello"]
"lowest"       → ["low", "est"]
"tokenization" → ["token", "ization"]
```

최악의 경우 글자 단위까지 쪼개면 되므로 미등록 단어가 발생하지 않고, 어휘 크기는 32,000 수준으로 고정할 수 있습니다. 앞으로 다룰 모델은 전부 이 방식을 씁니다.

## BPE

가장 널리 쓰이는 서브워드 알고리즘은 BPE(Byte Pair Encoding)입니다. 원래 1994년에 나온 데이터 압축 알고리즘인데, Sennrich et al.(2016)이 기계번역에 적용하며 표준이 되었습니다. **학습 파라미터도 언어학 지식도 필요 없고 빈도만 셉니다.**

모든 단어를 글자로 분해한 뒤, 가장 자주 인접해 나타나는 문자쌍을 찾아 병합하고 그 규칙을 기록합니다. 목표 어휘 크기에 도달할 때까지 반복하면 끝입니다.

논문의 예제 코퍼스로 따라가 보겠습니다.

```
low × 5    lower × 2    newest × 6    widest × 3
```

인접 쌍을 세면 `(e,s)`가 9회로 가장 많습니다. newest에 6번, widest에 3번 나오기 때문입니다. 이를 병합하고 다시 세면 `(es,t)`가 9회로 최다여서 `est`가 만들어집니다. 이어서 `(l,o)`와 `(lo,w)`가 각 7회로 병합되어 `low`가 생깁니다. 결과적으로 `es → est → lo → low` 순서로 어휘가 채워집니다. **빈도만 셌을 뿐인데 의미 단위에 가까운 조각이 나왔습니다.**

진짜 가치는 처음 보는 단어에서 드러납니다. 학습 코퍼스에 `lowest`는 한 번도 없었지만, 기록해둔 규칙을 순서대로 적용하면 이렇게 처리됩니다.

```
l o w e s t
→ (e+s)     l o w es t
→ (es+t)    l o w est
→ (l+o)     lo w est
→ (lo+w)    low est        결과: ["low", "est"]
```

`<unk>`가 나오지 않습니다. 그리고 `low`와 `est`의 의미는 다른 단어들에서 이미 학습된 상태이므로, **모델은 처음 보는 단어의 의미를 추론할 근거를 갖게 됩니다.**

변형도 몇 가지 있습니다. **WordPiece**는 빈도 대신 병합 후 우도 증가량으로 쌍을 고르며 BERT가 씁니다. **Unigram**은 반대로 큰 어휘에서 시작해 손실이 적은 토큰을 제거해 나가며 T5가 씁니다. **SentencePiece**는 알고리즘이 아니라 툴킷으로, 내부에서 BPE나 Unigram을 골라 쓰고 공백을 `▁`로 처리합니다.

# 3. 모델 입력 만들기

토큰이 정해지면 나머지는 기계적입니다. 사전을 조회해 정수로 바꾸고, 모델이 요구하는 특수 토큰을 붙이고, 배치 길이를 맞춥니다.

같은 `"Hello World!"`도 모델마다 결과가 다릅니다.

```
GPT-2   ['Hello', 'ĠWorld', '!']      [15496, 2159, 0]
BERT    ['hello', 'world', '!']       [101, 7592, 2088, 999, 102]
T5      ['▁Hello', '▁World', '!']     [8774, 1150, 55, 1]
```

출력에 보이는 `Ġ`, `##`, `▁`는 전부 단어 경계 표시입니다. 구현마다 방식이 다를 뿐 역할은 같습니다. 토큰 수가 3, 5, 4로 다른 이유는 특수 토큰 때문입니다. BERT는 앞뒤로 `[CLS]`와 `[SEP]`을 붙이고, T5는 끝에 `</s>`를 붙입니다. 번역 모델이라면 여기에 문장 시작을 알리는 `<bos>`와 생성을 멈추라는 `<eos>`가 더해집니다.

마지막으로 1장에서 미뤄둔 가변 길이 문제를 해결합니다. 배치 안에서 가장 긴 문장에 맞춰 나머지를 `<pad>`로 채우고, **어느 위치가 채움값인지 알려주는 마스크를 함께 넘깁니다.**

```
[ Hello, World, !,     <pad> ]        [1, 1, 1, 0]
[ The,   dog,   bit,   him   ]        [1, 1, 1, 1]
[ Yes,   <pad>, <pad>, <pad> ]        [1, 0, 0, 0]
```

**마스크를 빠뜨리면 모델이 `<pad>`를 실제 단어로 학습합니다.** 이 마스킹은 앞으로 attention과 Transformer를 다룰 때마다 계속 등장합니다.

# 4. 임베딩

여기까지 마치면 정수 텐서가 완성되지만, 1장에서 지적한 문제는 그대로 남아 있습니다. 15496과 2159는 여전히 크기를 비교할 수 없는 번호일 뿐입니다. 마지막 단계는 **각 ID에 실수 벡터를 하나씩 배정하는 것**입니다.

임베딩 행렬은 어휘 크기 V와 벡터 차원 d로 이루어진 **V × d 크기의 학습 가능한 파라미터**입니다. 앞에서 "V가 커지면 파라미터가 늘어난다"고 한 것이 바로 이 행렬을 두고 한 말입니다.

```
GPT-2   V = 50,257,  d = 768   →  38.6M 파라미터
BERT    V = 30,522,  d = 768   →  23.4M 파라미터
```

룩업은 이름 그대로 **행렬에서 해당 번호의 행을 꺼내오는 연산**입니다. 수식으로는 one-hot 벡터와 행렬의 곱이지만 결과가 특정 행 하나이므로, 실제 구현은 단순한 인덱싱입니다.

```
[15496, 2159, 0]  →  (3, 768) 실수 행렬

15496번 행  [ 0.021, -0.114,  0.087, ... ]   ← "Hello"
 2159번 행  [-0.052,  0.203, -0.011, ... ]   ← " World"
    0번 행  [ 0.134,  0.008, -0.076, ... ]   ← "!"
```

배치까지 포함하면 최종 입력은 `(batch, seq_len, d)` 모양이 됩니다. **여기서부터는 연속 공간이므로 gradient가 흐르고, 이미지와 같은 방식으로 학습이 진행됩니다.**

한 가지 짚어둘 것은 **임베딩이 전처리가 아니라 모델의 첫 레이어**라는 점입니다. 토크나이저의 병합 규칙과 사전도 학습된 결과물이지만 모델과 별도로 미리 학습해 고정한 것이라 역전파에 참여하지 않습니다. 반면 임베딩 행렬은 옵티마이저가 갱신합니다. 컴퓨터 비전에 대응시키면 리사이즈와 정규화가 전처리, 첫 conv 레이어가 임베딩에 해당합니다.

그래서 어휘에 토큰을 추가할 때는 행렬도 함께 키워야 합니다.

```python
tokenizer.add_tokens(["myoglobin", "hemoglobin"])
model.resize_token_embeddings(len(tokenizer))
```

두 번째 줄을 빠뜨리면 새 토큰 ID가 행렬 범위를 벗어나 오류가 납니다. 새로 생긴 행은 **랜덤 초기화 상태**이며 학습을 거치기 전까지 아무 의미도 담고 있지 않습니다.

사실 이것은 새로 추가한 행만의 이야기가 아닙니다. 임베딩 행렬은 처음에 전부 랜덤 값으로 시작합니다. 그렇다면 이 숫자들은 어떻게 의미를 갖게 되는 걸까요. 다음 글에서 다루겠습니다.
