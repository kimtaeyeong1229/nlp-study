# 머리말

우리는 보통 딥러닝을 공부할 때 이미지 데이터를 우선적으로 배우게 됩니다. 이미지 데이터는 형태 자체가 정수형으로 이루어져 있어, 딥러닝 혹은 머신러닝 모델에 입력할 때 별도의 어려움 없이 입력할 수 있습니다. 하지만 우리가 사용하는 자연어를 생각하면 모델에 어떻게 입력해야 하는지 의문이 생깁니다. `"Hello World!"`를 어떻게 딥러닝 모델에 입력할까요?

이미지와 자연어의 차이는 두 가지입니다. 첫째, **이미지에는 픽셀이라는 최소 단위가 이미 정해져 있지만 자연어에는 없습니다.** `"Hello World!"`를 `Hello / World / !`로 자를지 `He / llo / Wor / ld / !`로 자를지는 데이터가 아니라 설계자가 정합니다. 둘째, **이미지는 크기가 달라도 리사이즈로 맞출 수 있지만 문장에는 길이를 줄이는 연산이 없습니다.** 단어를 절반으로 자를 수는 없기 때문입니다.

이번 글에서는 **GPT-2를 기준으로** `"Hello World!"`라는 문자열이 전처리를 거쳐 임베딩 벡터가 되기까지의 다섯 단계를 따라가 보겠습니다. 실제로 토크나이저를 열어 확인한 값을 그대로 씁니다.

# 목차

1. 토큰화
2. 정수 인코딩
3. 특수 토큰
4. 패딩과 어텐션 마스크
5. 임베딩 룩업

# 1. 토큰화

모델은 아무 글자나 받지 않습니다. **미리 만들어둔 단어장에 있는 조각으로만** 문장을 표현해야 합니다. 이 단어장을 어휘(vocabulary)라고 부릅니다. 그럼 이 단어장에 무엇을 담아야 할까요.

가장 직관적인 방법은 **공백으로 잘라 단어를 그대로 담는 것**입니다. 하지만 두 가지 문제가 있습니다. 첫째, 학습 때 보지 못한 단어는 전부 `<unk>` 하나로 처리되어 정보가 통째로 사라집니다. 고유명사, 신조어, 오타가 모두 같은 토큰이 됩니다. 둘째, 어휘가 폭발합니다. 영어만 해도 활용형까지 포함하면 수십만 개인데, 어휘가 커지면 뒤에 나올 임베딩 행렬도 함께 커집니다.

반대로 **글자 단위로 자르면** 어휘는 100개 남짓으로 줄고 모르는 단어도 사라집니다. 대신 시퀀스가 5~10배 길어지고, 토큰 하나에 의미가 없어서 모델이 글자를 단어로 조합하는 것부터 배워야 합니다.

답은 중간에 있습니다. **자주 나오는 단어는 통째로 두고, 드문 단어만 조각으로 쪼개는** 서브워드 방식입니다.

```
"Hello"        → ["Hello"]
"lowest"       → ["low", "est"]
"tokenization" → ["token", "ization"]
```

이러면 최악의 경우 글자까지 내려가면 되므로 **모르는 단어라는 게 원칙적으로 사라지고**, 어휘 크기도 고정할 수 있습니다. GPT-2는 이 방식으로 어휘를 50,257개로 맞췄습니다.

## BPE

GPT가 쓰는 서브워드 알고리즘은 BPE(Byte Pair Encoding)입니다. 원래 1994년에 나온 데이터 압축 알고리즘인데, Sennrich et al.(2016)이 기계번역에 적용하며 표준이 되었습니다. 동작은 단순합니다. 모든 단어를 글자로 분해한 뒤 **가장 자주 붙어 나오는 문자쌍을 찾아 합치는 일을 반복**하고, 그 규칙을 순서대로 기록해둡니다.

```
low × 5    lower × 2    newest × 6    widest × 3
```

이 코퍼스에서는 `(e,s)`가 9회로 가장 많으니 먼저 합칩니다. 다시 세면 `(es,t)`가 최다여서 `est`가 만들어지고, 이어서 `(l,o)`와 `(lo,w)`가 합쳐져 `low`가 생깁니다. **빈도만 셌을 뿐인데 사람이 봐도 말이 되는 조각이 나왔습니다.**

진짜 가치는 처음 보는 단어에서 드러납니다. 이 코퍼스에 `lowest`는 한 번도 없었지만, 기록해둔 규칙을 순서대로 적용하면 그만입니다.

```
l o w e s t
→ (e+s)     l o w es t
→ (es+t)    l o w est
→ (l+o)     lo w est
→ (lo+w)    low est        결과: ["low", "est"]
```

`<unk>`가 나오지 않습니다. 그리고 `low`와 `est`가 무슨 뜻인지는 다른 단어들에서 이미 배운 상태이므로, **모델은 처음 보는 단어의 의미를 추측할 근거를 갖게 됩니다.**

# 2. 정수 인코딩

어휘가 정해졌으니 조각마다 번호를 붙입니다. 단어장의 몇 번째 항목인지 적어두는 사전 조회에 지나지 않습니다.

```
"Hello World!"  →  ['Hello', 'ĠWorld', '!']  →  [15496, 2159, 0]
```

토큰에 붙은 `Ġ`는 **앞에 띄어쓰기가 있었다는 표시**입니다. 나중에 토큰을 다시 문장으로 되돌려야 하므로 공백도 정보로 남겨둡니다.

여기서 짚어둘 것은 **이 번호가 사물함 번호와 같다**는 점입니다. 15496번이 2159번보다 크거나 좋을 이유가 없습니다. 그냥 위치일 뿐이고, 어휘를 다른 순서로 정렬하면 번호도 완전히 달라집니다. **크기를 비교하거나 더하는 것이 아무 의미가 없는 상태**입니다. 이 문제는 마지막 장에서 해결합니다.

그 전에, 숫자로 바뀌었다고 해서 바로 모델에 넣을 수 있는 것은 아닙니다. 모델이 요구하는 신호를 붙이고(3장) 배치 모양을 맞춰야(4장) 합니다.

# 3. 특수 토큰

문장 자체에는 없지만 모델을 돌리려면 필요한 토큰이 있습니다. GPT-2의 토크나이저를 열어보면 이렇게 되어 있습니다.

```
bos_token  = '<|endoftext|>'   id = 50256
eos_token  = '<|endoftext|>'   id = 50256
unk_token  = '<|endoftext|>'   id = 50256
pad_token  = None
```

**전부 같은 토큰 하나이고, 채움용 토큰은 아예 없습니다.** 어휘 50,257개 중 50,256개가 BPE 토큰이고 나머지 하나가 이것입니다.

이렇게 단순한 이유는 GPT가 **문서를 죽 이어붙여 학습하는 디코더 단독 모델**이기 때문입니다. 필요한 것은 "여기서 문서가 끊긴다"는 표시 하나뿐이고, 앞 문서의 끝이 곧 다음 문서의 시작이니 시작과 끝을 구분할 이유가 없습니다.

그래도 역할은 중요합니다. 생성 모델은 언제 멈출지 스스로 판단해야 하는데 그 기준이 이 토큰을 출력하는 순간이고, **이 신호가 없으면 모델은 끝을 모르고 계속 만들어냅니다.** 토크나이저가 자동으로 붙여주지는 않으므로 필요하면 직접 넣습니다.

```
"Hello World!"                  →  [15496, 2159, 0]
"Hello World!<|endoftext|>"     →  [15496, 2159, 0, 50256]
```

참고로 번역 모델처럼 **인코더와 디코더가 나뉜 구조에서는 이 토큰들을 따로 둡니다.** 시작을 알리는 `<sos>`, 끝을 알리는 `<eos>`, 길이를 맞추는 `<pad>`, 어휘에 없는 토큰을 대신하는 `<unk>`를 각각 씁니다. 디코더가 빈 상태에서 출력을 시작해야 하므로 첫 입력으로 넣어줄 `<sos>`가 반드시 필요하기 때문입니다.

# 4. 패딩과 어텐션 마스크

이제 머리말에서 미뤄둔 문제를 해결할 차례입니다. 문장 길이는 제각각인데 텐서는 직사각형이어야 합니다.

배치에서 가장 긴 문장에 맞춰 나머지를 `<pad>`로 채웁니다. GPT-2에는 채움용 토큰이 없으므로 보통 `<|endoftext|>`를 지정해 씁니다. 그리고 **어느 자리가 채움값인지 알려주는 마스크를 함께 넘깁니다.**

```
[ Hello, World, !,     <pad> ]        [1, 1, 1, 0]
[ The,   dog,   bit,   him   ]        [1, 1, 1, 1]
[ Yes,   <pad>, <pad>, <pad> ]        [1, 0, 0, 0]
```

마스크가 왜 필요한지는 **attention의 계산 방식**을 봐야 이해됩니다. RNN처럼 앞에서부터 순서대로 읽는 구조라면 실제 길이만큼만 돌리고 멈추면 그만입니다. 하지만 attention은 그렇게 동작하지 않습니다. **모든 위치가 모든 위치를 한 번에 참조합니다.** `Hello`가 자기 표현을 만들 때 `World`와 `!`는 물론이고 뒤에 붙은 `<pad>`까지 전부 쳐다봅니다.

게다가 attention 가중치는 softmax로 계산되므로 **아무 의미 없는 `<pad>`에도 0이 아닌 값이 배정됩니다.** 그 비중만큼 실제 토큰의 표현이 오염됩니다.

마스크는 이 문제를 막습니다. 마스크가 0인 자리의 점수를 softmax 직전에 음의 무한대로 바꿔버리면 가중치가 정확히 0이 되어 계산에서 완전히 빠집니다. **`<pad>`가 존재하지 않았던 것처럼 만드는 장치**입니다.

# 5. 임베딩 룩업

여기까지 오면 정수 텐서가 완성되지만, 2장에서 지적한 문제는 그대로입니다. 15496과 2159는 여전히 사물함 번호일 뿐입니다. 마지막 단계는 **그 번호로 실제 내용물을 꺼내오는 것**입니다.

임베딩 행렬은 어휘 크기 V와 벡터 차원 d로 이루어진 **V × d 크기의 표**입니다. 행이 어휘 개수만큼 있고, 각 행에 d개의 숫자가 들어 있습니다. GPT-2는 V = 50,257, d = 768이므로 이 표 하나가 38.6M 파라미터입니다.

룩업은 이름 그대로 **표에서 해당 번호의 행을 꺼내오는 연산**입니다. 수식으로는 one-hot 벡터와 행렬의 곱이지만 결과가 특정 행 하나이므로, 실제 구현은 단순한 인덱싱입니다.

```
[15496, 2159, 0]  →  (3, 768)

15496번 행  [ 0.021, -0.114,  0.087, ... ]   ← "Hello"
 2159번 행  [-0.052,  0.203, -0.011, ... ]   ← " World"
    0번 행  [ 0.134,  0.008, -0.076, ... ]   ← "!"
```

**이 순간 데이터의 성질이 바뀝니다.** 15496이라는 번호는 더하거나 빼도 의미가 없었지만, 768개의 실수는 더하고 빼고 미분할 수 있습니다. 이미지 픽셀과 같은 세계로 들어온 것입니다. 배치까지 포함하면 최종 입력은 `(batch, seq_len, d)` 모양이 됩니다.

# 마무리

GPT-2가 `"Hello World!"`를 받아들이는 과정을 한 줄로 줄이면 이렇습니다.

**어휘를 정하고 → 문장을 그 조각으로 쪼개고 → 번호를 매기고 → 신호와 모양을 맞추고 → 그 번호로 표에서 벡터를 꺼내옵니다.**

여기서 **앞의 네 단계와 마지막 단계는 성격이 다릅니다.** 토크나이저의 병합 규칙과 어휘도 학습으로 만들어졌지만 모델과 별도로 미리 만들어 고정한 것이라 역전파에 참여하지 않습니다. 반면 임베딩 행렬은 옵티마이저가 갱신합니다. **임베딩은 전처리가 아니라 모델의 첫 레이어입니다.**

특수 토큰 구성이나 서브워드 알고리즘은 모델마다 조금씩 다르지만, 이 다섯 단계라는 큰 틀은 앞으로 다룰 모든 모델이 공유합니다.

그런데 그 표는 **처음에 전부 랜덤 숫자**입니다. 아무 의미도 없는 값에서 시작해 학습을 거치며 자리를 잡습니다. 그렇다면 이 숫자들은 어떻게 의미를 갖게 되는 걸까요. 다음 글에서 다루겠습니다.
