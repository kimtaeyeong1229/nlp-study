우리는 보통 딥러닝을 공부할 때 이미지 데이터를 우선적으로 배우게 됩니다. 이미지 데이터는 형태 자체가 정수형으로 이루어져 있어, 딥러닝 혹은 머신러닝 모델에 입력할 때 별도의 어려움 없이 입력할 수 있습니다. 하지만 우리가 사용하는 자연어를 생각하면 모델에 어떻게 입력해야 하는지 의문이 생깁니다. `"Hello World!"`를 어떻게 딥러닝 모델에 입력할까요?

이번 글에서는 이 의문에서 출발합니다. 먼저 이미지 데이터와 텍스트 데이터가 무엇이 다른지 짚어보고, 그다음 `"Hello World!"`라는 문자열이 모델에 들어갈 수 있는 정수 텐서가 되기까지 거치는 과정을 순서대로 따라가 보겠습니다.

# 1. 이미지 데이터와의 차이

이미지의 픽셀 값은 **연속적인 값**입니다. 130과 131 사이에는 130.5가 있고, 그 값도 "조금 더 밝다"는 의미를 가집니다. 값을 조금 바꾸면 결과도 조금 바뀌기 때문에 gradient가 자연스럽게 정의됩니다.

반면 텍스트를 숫자로 바꾸면 **이산적인 기호**가 됩니다. GPT-2 토크나이저에서 `Hello`는 15496번, `World`는 2159번인데, 이 번호는 사전의 몇 번째 항목인지를 나타낼 뿐이라 크기를 비교하는 것은 아무 의미가 없습니다. 사전을 다른 기준으로 정렬하면 번호도 완전히 달라집니다. 그래서 자연어 처리에는 컴퓨터 비전에 없는 단계가 하나 더 필요합니다. **이산 기호를 연속 벡터로 옮기는 과정**, 즉 임베딩입니다. 그리고 임베딩을 하려면 그 전에 **무엇을 하나의 기호로 볼 것인지**부터 정해야 하는데, 이것이 이번 글의 핵심 질문입니다.

크기를 다루는 방식도 다릅니다. 이미지는 크기가 제각각이어도 리사이즈나 크롭으로 맞출 수 있지만, **문장에는 길이를 줄이는 연산이 없습니다.** 단어를 절반으로 줄일 수는 없기 때문입니다. 두 단어짜리 `"Hello World!"`와 500단어짜리 문서를 같은 텐서에 담아야 하는데, 이 문제는 뒤에서 패딩과 마스크로 해결하게 됩니다.

최소 단위의 성격은 오히려 반대입니다. 픽셀 하나는 아무 의미가 없고, 의미는 픽셀이 모여 만드는 패턴에서 생깁니다. CNN이 하는 일이 바로 그 조립 과정입니다. 하지만 토큰은 하나만으로도 의미를 가집니다. 더 중요한 차이는 **픽셀은 주어지는 값이지만 토큰은 우리가 정하는 단위**라는 점입니다. `"Hello World!"`를 `Hello / World / !`로 볼지 `He / llo / Wor / ld / !`로 볼지는 데이터가 아니라 설계자가 결정합니다.

순서가 갖는 의미도 정반대입니다. CNN은 고양이가 어디에 있든 고양이로 인식하도록 translation invariance를 얻으려 하지만, **텍스트는 순서가 바뀌면 의미가 바뀝니다.** `"Hello World"`와 `"World Hello"`는 같은 단어로 이루어져 있지만 하나만 인사말입니다. Self-attention은 그 자체로 순서를 인식하지 못하기 때문에, Transformer는 positional encoding을 따로 붙여 위치 정보를 넣어줍니다.

여기에 더해 **텍스트는 멀리 떨어진 단어끼리 얽히는 경우가 흔합니다.** 인접 픽셀이 강하게 연관되어 있어 3×3 커널이 통하는 이미지와 달리, 문장에서는 열 단어 넘게 떨어진 주어와 동사가 수 일치로 묶이기도 합니다. 고정 크기 커널로는 이런 관계를 포착하기 어렵고, 이것이 RNN에서 attention으로, 다시 Transformer로 이어진 흐름의 배경입니다.

다만 **컴퓨터 비전에서 배운 것이 버려지지는 않습니다.** Residual connection과 LayerNorm은 Transformer 블록을 이루는 핵심 부품이고, multi-head attention은 여러 커널로 서로 다른 패턴을 뽑는 CNN의 직관과 통합니다. ImageNet으로 사전학습한 뒤 파인튜닝하는 방식도 뒤에서 볼 사전학습 언어 모델과 정확히 같은 발상입니다. **차이는 대부분 입력을 만드는 앞단에 몰려 있습니다.**

# 2. 텍스트 입력 파이프라인

## 2.1. 전체 흐름

- `"Hello World!"`가 모델에 들어가기까지 여섯 단계를 거침 (GPT-2 기준)

```
"Hello World!"
  ↓ ① 정규화
  ↓ ② 사전 분할
  ↓ ③ 토큰화
["Hello", "ĠWorld", "!"]
  ↓ ④ 어휘 매핑
[15496, 2159, 0]
  ↓ ⑤ 특수 토큰 추가
  ↓ ⑥ 패딩 + 마스크
정수 텐서 → 임베딩 룩업 → 모델
```

## 2.2. 정규화와 사전 분할

- **정규화**는 유니코드 정규화, 소문자화, 제어문자 정리를 수행함
- 소문자화하면 어휘가 줄어들지만 `Apple`과 `apple`을 구분할 단서를 잃음
- BERT에 `bert-base-uncased`와 `bert-base-cased`가 따로 존재하는 이유이며, **최근 모델은 대소문자를 유지하는 방향으로 정착함**
- **사전 분할**은 토큰화 전에 공백과 구두점 기준으로 텍스트를 미리 잘라두는 단계임
- 문장 전체에서 문자쌍 빈도를 세는 것보다 단어 단위로 세는 쪽이 훨씬 빠르고, **서브워드 조각이 단어 경계를 넘지 않도록 막아줌**
- 같은 `"Hello World!"`도 구현마다 공백 처리 방식이 다름

```
GPT-2   ['Hello', 'ĠWorld', '!']     공백을 Ġ로 변환
BERT    ['hello', 'world', '!']      단어 중간 조각에 ## 접두사
T5      ['▁Hello', '▁World', '!']    공백을 ▁로 변환
```

- 토크나이저 출력에 이런 기호가 보이면 **단어 경계 표시**로 해석하면 됨

## 2.3. 토큰화 단위 선택

- 파이프라인에서 **가장 중요한 결정**이며, 무엇을 하나의 단위로 볼지 정하는 단계임

**단어 단위**

- 공백 기준으로 자르는 가장 직관적인 방식이지만 세 가지 문제가 있음
- **미등록 단어(OOV)** — 학습 때 보지 못한 단어가 전부 `<unk>` 하나로 처리되어 고유명사, 신조어, 오타의 정보가 소실됨
- **어휘 폭발** — 영어만 해도 활용형까지 포함하면 수십만 개이며, V = 200,000에 d = 512면 임베딩 행렬만 1억 파라미터임
- **형태론적 관계 소실** — `run`, `runs`, `running`이 서로 무관한 ID가 되어 희귀 활용형은 학습되지 않음

**문자 단위**

- 어휘가 100개 남짓으로 줄고 OOV가 사라짐
- 대신 **시퀀스 길이가 5~10배 증가**하며, Transformer의 attention은 길이의 제곱에 비례하므로 부담이 큼
- 토큰 하나에 의미가 없어 모델이 글자를 단어로 조합하는 것부터 학습해야 함

**서브워드**

- 두 방식의 절충안이며 원칙은 **자주 나오는 단어는 통째로, 드문 단어는 조각으로**

```
"Hello"        → ["Hello"]
"lowest"       → ["low", "est"]
"tokenization" → ["token", "ization"]
```

- 최악의 경우 글자 단위까지 쪼개면 되므로 **OOV가 발생하지 않음**
- 어휘 크기를 32,000 수준으로 고정할 수 있음
- `low`와 `lowest`가 조각을 공유하므로 형태론적 관계가 일부 반영됨
- **이후 다룰 모델(GNMT, Transformer, BART, T5)이 전부 서브워드를 사용함**

## 2.4. BPE

- Byte Pair Encoding, 원래 1994년에 나온 **데이터 압축 알고리즘**임
- Sennrich et al. (2016)이 기계번역 토큰화에 적용하며 표준이 됨
- **학습 파라미터도 언어학 지식도 필요 없고 빈도만 계산함**
- 동작은 네 단계임
  1. 모든 단어를 글자 단위로 분해함
  2. 가장 자주 인접해 나타나는 문자쌍을 찾음
  3. 해당 쌍을 하나의 토큰으로 병합하고 규칙을 기록함
  4. 목표 어휘 크기에 도달할 때까지 2~3을 반복함

**병합 과정** (Sennrich 논문의 예제 코퍼스)

```
low × 5    lower × 2    newest × 6    widest × 3
```

- 인접 쌍을 세면 `(e,s)`가 9회로 최다임 (newest 6 + widest 3) → 병합
- 다음은 `(es,t)` 9회 → 병합하여 `est` 생성
- 이어서 `(l,o)` 7회, `(lo,w)` 7회 → 병합하여 `low` 생성
- 어휘 추가 순서는 `es → est → lo → low`
- **빈도만 셌는데 의미 단위에 가까운 조각이 만들어짐**

**미등록 단어 처리**

- 학습 코퍼스에 `lowest`는 **한 번도 없었지만** 기록된 규칙을 순서대로 적용하면 처리됨

```
l o w e s t
→ (e+s)     l o w es t
→ (es+t)    l o w est
→ (l+o)     lo w est
→ (lo+w)    low est        결과: ["low", "est"]
```

- `<unk>`가 발생하지 않으며, `low`와 `est`의 의미는 다른 단어에서 이미 학습된 상태임
- **처음 보는 단어의 의미를 추론할 근거가 확보됨**

**변형 알고리즘**

- **WordPiece** — 빈도 대신 병합 후 언어 모델 우도 증가량으로 쌍을 선택하며, BERT와 GNMT가 사용함
- **Unigram LM** — 큰 어휘에서 시작해 손실이 적은 토큰을 제거해 나가며, T5와 mT5가 사용함
- **SentencePiece** — 알고리즘이 아니라 **툴킷**이며, 내부적으로 BPE 또는 Unigram을 선택해 사용함. 공백을 `▁`로 처리해 띄어쓰기 규칙이 다른 언어에서도 일관되게 동작함

## 2.5. 어휘 매핑과 확장

- 토큰을 정수로 바꾸는 사전 조회 과정임

```python
["Hello", "ĠWorld", "!"] → [15496, 2159, 0]
```

- 여기서 **어휘 크기 V가 확정됨**
- 임베딩 행렬이 V × d이고 출력층 softmax도 V 크기이므로, **V가 커지면 파라미터가 선형으로 증가함**
- 어휘를 키우면 시퀀스는 짧아지지만 파라미터는 늘어나며, **이 트레이드오프가 토큰화 방식 선택의 근거임**
- 도메인 전문 용어가 계속 잘게 쪼개지면 토크나이저에 직접 추가할 수 있음

```python
tokenizer.add_tokens(["myoglobin", "hemoglobin"])
model.resize_token_embeddings(len(tokenizer))
```

- 어휘가 늘었으므로 **임베딩 행렬도 함께 키워야 하며**, 누락하면 새 토큰 ID가 행렬 범위를 벗어나 오류가 발생함
- 새로 생긴 임베딩 행은 **랜덤 초기화 상태**이며 학습 전까지 아무 의미도 담고 있지 않음

## 2.6. 특수 토큰과 패딩

- 모델 동작을 위해 예약된 토큰이 붙음
- `<bos>` 문장 시작이자 디코더의 첫 입력, `<eos>` 생성 종료 신호, `<pad>` 길이 맞춤용 채움값, `<mask>` 사전학습에서 가려진 토큰
- 같은 `"Hello World!"`도 모델마다 붙는 토큰이 다름

```
GPT-2   [15496, 2159, 0]                    특수 토큰 없음
BERT    [101, 7592, 2088, 999, 102]         앞뒤로 [CLS], [SEP]
T5      [8774, 1150, 55, 1]                 끝에 </s>
```

- 번역 태스크에서는 디코더 입력과 정답이 **한 칸씩 밀려 있으며**, 이를 teacher forcing이라 부름

```
인코더 입력:  Hello World ! <eos>
디코더 입력:  <bos> Bonjour le monde !
디코더 정답:  Bonjour le monde ! <eos>
```

- 마지막으로 1장에서 미뤄둔 **가변 길이 문제**를 해결함
- 배치 내 최대 길이에 맞춰 나머지를 `<pad>`로 채우고, **마스크를 함께 전달해 `<pad>` 위치를 계산에서 제외함**

```
[ Hello, World, !,     <pad> ]        [1, 1, 1, 0]
[ The,   dog,   bit,   him   ]        [1, 1, 1, 1]
[ Yes,   <pad>, <pad>, <pad> ]        [1, 0, 0, 0]
```

- **마스크를 누락하면 모델이 `<pad>`를 실제 단어로 학습함**
- 여기까지 마치면 정수 텐서가 완성되며, 다음은 임베딩 룩업임
