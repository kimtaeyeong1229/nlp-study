# 1주차. 토큰화와 텍스트 입력 파이프라인

자연어를 다루는 모델은 결국 숫자만 계산한다. 그래서 어떤 모델을 공부하든 "문장이 어떤 형태로 모델에 들어가는가"를 먼저 알아야 그 뒤의 구조가 이해된다. 토큰을 무엇으로 잡느냐에 따라 어휘 크기가 정해지고, 어휘 크기가 임베딩 행렬과 출력층 크기를 결정하며, 시퀀스 길이가 곧 연산량이 된다. 앞으로 12주 동안 볼 SMT부터 T5까지 모든 모델이 이 단계를 똑같이 거치기 때문에, 여기를 건너뛰면 매 주차마다 입력이 무엇인지 설명하지 못한 채 구조만 훑게 된다.

---

# 1. 이미지 데이터와의 차이

## 1.1. 값의 연속성

- 픽셀 값은 연속 공간에 존재함
- 130과 131 사이에 130.5가 있고, 그 값도 의미를 가짐 (조금 밝아진 것)
- 값을 조금 바꾸면 결과도 조금 바뀌므로 gradient가 자연스럽게 정의됨
- 토큰 ID는 이산 심볼이며 크기 비교가 무의미함
- 130번이 `apple`, 131번이 `zebra`라면 두 번호 사이에 아무 관계도 없음
- 사전 정렬 기준(알파벳순/빈도순)에 따라 번호가 완전히 달라짐
- 따라서 NLP에는 CV에 없는 단계가 추가됨 — **이산 심볼을 연속 벡터로 변환** (임베딩, 2주차)
- 임베딩 이전에 "무엇을 하나의 심볼로 볼 것인가"를 먼저 정해야 함

## 1.2. 입력 크기

- 이미지는 크기가 달라도 리사이즈나 크롭으로 맞출 수 있음
- 문장은 길이를 줄이는 연산이 없음
- 5단어 문장과 500단어 문장을 같은 텐서에 담아야 함
- 해결책은 패딩과 마스킹이며 2.7.에서 다룸

## 1.3. 최소 단위의 의미

- 픽셀 하나는 의미를 가지지 않음
- `(128, 64, 32)` 값 하나로 알 수 있는 것이 없고, 의미는 픽셀들이 모여 만드는 패턴에서 발생함
- CNN이 하는 일이 그 조립 과정임
- 토큰은 하나만으로도 의미를 가짐 (`cat`)
- 픽셀은 주어지는 값이지만 토큰은 설계자가 정하는 단위임
- 따라서 **최소 단위를 무엇으로 잡을지가 설계 결정**이 됨

## 1.4. 순서 정보

- CNN은 translation invariance를 목표로 함 (고양이가 어디 있든 고양이)
- 텍스트는 반대로 순서가 바뀌면 의미가 바뀜

```
The dog bit the man
The man bit the dog
```

- 단어 구성이 같아도 의미가 완전히 다름
- Self-attention은 그 자체로 순서를 인식하지 못함
- 그래서 Transformer가 positional encoding을 별도로 추가함 (7주차)

## 1.5. 의존 거리

- 인접 픽셀은 강하게 연관되어 있어 3×3 커널이 유효함
- 텍스트는 멀리 떨어진 단어끼리 얽히는 경우가 흔함

```
The keys that I left on the kitchen table this morning are missing
```

- `keys`와 `are`는 9단어 떨어져 있지만 수 일치로 묶여 있음
- 고정 크기 커널로는 포착하기 어려움
- RNN → attention → Transformer로 이어진 흐름의 배경임

## 1.6. 차이 요약

- **값** — 이미지는 연속, 텍스트는 이산
- **크기** — 이미지는 리사이즈로 고정, 텍스트는 가변이라 패딩 필요
- **최소 단위** — 픽셀은 의미 없음, 토큰은 의미 있음
- **순서** — 이미지는 불변이 유리, 텍스트는 순서가 의미를 결정
- **의존 거리** — 이미지는 지역적, 텍스트는 장거리도 흔함

## 1.7. 재사용되는 CV 개념

- Residual connection과 LayerNorm은 Transformer 블록의 핵심 구성요소임 (7주차)
- Multi-head attention은 여러 커널로 서로 다른 패턴을 뽑는 CNN 직관과 통함
- ImageNet 사전학습 후 파인튜닝하는 방식은 9주차 사전학습 모델과 동일한 발상임
- 차이는 입력 처리 단계에 집중되어 있고, 뒤로 갈수록 익숙한 개념이 많아짐

# 2. 텍스트 입력 파이프라인

## 2.1. 전체 흐름

```
원문 텍스트
  ↓ ① 정규화
  ↓ ② 사전 분할
  ↓ ③ 토큰화
토큰 리스트
  ↓ ④ 어휘 매핑
정수 ID
  ↓ ⑤ 특수 토큰 추가
  ↓ ⑥ 패딩 + 마스크
정수 텐서
  ↓   임베딩 룩업 (2주차)
실수 벡터 → 모델
```

## 2.2. 정규화

- 유니코드 정규화, 소문자화, 제어문자 정리를 수행함
- 소문자화하면 `Apple`과 `apple`이 같은 토큰이 되어 어휘가 줄어듦
- 대신 회사명과 과일을 구분할 단서를 잃음
- BERT에 `bert-base-uncased`와 `bert-base-cased`가 따로 존재하는 이유임
- 최근 모델은 대소문자를 유지하는 방향으로 정착함

## 2.3. 사전 분할

- 토큰화 전에 공백과 구두점 기준으로 텍스트를 미리 잘라두는 단계임
- 문장 전체에서 문자쌍 빈도를 세는 것보다 단어 단위로 세는 쪽이 훨씬 빠름
- 서브워드 조각이 단어 경계를 넘지 않도록 막는 역할도 함
- 단어 시작 표시가 구현마다 다름
  - GPT-2 — 공백을 `Ġ`로 변환
  - BERT — 단어 중간 조각에 `##` 접두사
  - T5 / SentencePiece — 공백을 `▁`로 변환
- 토크나이저 출력에 이 기호들이 보이면 단어 경계 표시로 해석하면 됨

## 2.4. 토큰화

- 파이프라인에서 가장 중요한 단계임
- 무엇을 하나의 단위로 볼지 결정함

### 2.4.1. 단어 단위 토큰화

- 공백 기준으로 자르는 가장 직관적인 방식임
- 세 가지 문제가 발생함

**미등록 단어(OOV)**

- 학습 때 보지 못한 단어가 전부 `<unk>` 하나로 처리됨
- 고유명사, 신조어, 오타가 모두 같은 토큰이 됨
- 번역에서는 단어를 틀리는 수준이 아니라 정보가 소실됨

**어휘 폭발**

- 영어만 해도 활용형까지 포함하면 수십만 개임
- V = 200,000, d = 512면 임베딩 행렬만 1억 파라미터임
- 출력층 softmax도 동일한 크기라 계산량이 함께 증가함

**형태론적 관계 소실**

- `run`, `runs`, `running`, `ran`이 서로 무관한 ID가 됨
- 희귀 활용형은 데이터가 부족해 학습되지 않음

### 2.4.2. 문자 단위 토큰화

- 어휘가 100개 남짓으로 줄고 OOV가 사라짐
- 시퀀스 길이가 5~10배 증가함
- Transformer의 attention은 길이의 제곱에 비례하므로 부담이 큼
- 토큰 하나에 의미가 없어 모델이 글자를 단어로 조합하는 것부터 학습해야 함

### 2.4.3. 서브워드 토큰화

- 두 방식의 절충안임
- 원칙 — **자주 나오는 단어는 통째로, 드문 단어는 조각으로**

```
"cat"          → ["cat"]
"lowest"       → ["low", "est"]
"tokenization" → ["token", "ization"]
```

- 세 문제가 동시에 해결됨
  - 최악의 경우 글자 단위까지 쪼개면 되므로 OOV가 없음
  - 어휘 크기를 32,000 수준으로 고정할 수 있음
  - `low`와 `lowest`가 조각을 공유하므로 형태론적 관계가 일부 반영됨
- 이후 다룰 모델(GNMT, Transformer, BART, T5)이 전부 서브워드를 사용함

### 2.4.4. BPE 알고리즘

- Byte Pair Encoding, 1994년에 나온 데이터 압축 알고리즘임
- Sennrich et al. (2016)이 기계번역 토큰화에 적용하며 표준이 됨
- 학습 파라미터도 언어학 지식도 필요 없고 빈도만 계산함

**동작 순서**

1. 모든 단어를 글자 단위로 분해함
2. 가장 자주 인접해 나타나는 문자쌍을 찾음
3. 해당 쌍을 하나의 토큰으로 병합하고 규칙을 기록함
4. 목표 어휘 크기에 도달할 때까지 2~3을 반복함

**예제 코퍼스**

```
low     × 5
lower   × 2
newest  × 6
widest  × 3
```

- 인접 쌍을 세면 `(e,s)`가 9회로 최다임 (newest 6 + widest 3) → 병합
- 다음은 `(es,t)`가 9회 → 병합, `est` 생성
- 이어서 `(l,o)` 7회, `(lo,w)` 7회 → 병합, `low` 생성
- 어휘 추가 순서

```
es → est → lo → low
```

- 빈도만 셌는데 의미 단위에 가까운 조각이 생성됨

### 2.4.5. 미등록 단어 처리

- 학습 코퍼스에 `lowest`는 존재하지 않았음
- 기록된 병합 규칙을 순서대로 적용하면 처리됨

```
l o w e s t
→ (e+s)    l o w es t
→ (es+t)   l o w est
→ (l+o)    lo w est
→ (lo+w)   low est

결과: ["low", "est"]
```

- `<unk>`가 발생하지 않음
- `low`와 `est`의 의미는 다른 단어들에서 이미 학습된 상태임
- 처음 보는 단어의 의미를 추론할 근거가 확보됨

### 2.4.6. WordPiece와 Unigram

- **WordPiece** — 빈도 대신 병합 후 언어 모델 우도 증가량으로 쌍을 선택함
  - Google BERT, GNMT(6주차)에서 사용
  - 단어 중간 조각에 `##`을 붙임
- **Unigram LM** — 큰 어휘에서 시작해 손실이 적은 토큰을 제거해 나감
  - T5, mT5(12주차)에서 사용
- **SentencePiece** — 알고리즘이 아니라 툴킷임
  - 내부적으로 BPE 또는 Unigram을 선택해 사용함
  - 공백을 `▁`로 처리해 띄어쓰기 규칙이 다른 언어에서도 일관되게 동작함

## 2.5. 어휘 매핑

- 토큰을 정수로 변환하는 사전 조회 과정임

```python
["I", "love", "cats"] → [40, 1842, 11875]
```

### 2.5.1. 어휘 크기와 임베딩 행렬

- 임베딩 행렬 크기가 V × d이므로 V가 커지면 파라미터가 선형으로 증가함
- 출력층 softmax도 V 크기임
- 어휘 크기를 키우면 시퀀스는 짧아지지만 파라미터는 늘어남
- 이 트레이드오프가 토큰화 방식 선택의 근거임

### 2.5.2. 어휘 확장

- 도메인 전문 용어가 계속 잘게 쪼개지는 상황이 실무에서 자주 발생함
- 한 개념이 매번 5토큰을 차지하면 시퀀스가 길어지고 모델이 하나의 단위로 학습하기 어려움
- 토크나이저에 직접 추가할 수 있음

```python
tokenizer.add_tokens(["myoglobin", "hemoglobin"])
model.resize_token_embeddings(len(tokenizer))
```

- 어휘가 늘었으므로 임베딩 행렬도 함께 키워야 함
- `resize_token_embeddings`를 누락하면 새 토큰 ID가 행렬 범위를 벗어나 오류가 발생함
- 새로 생성된 임베딩 행은 랜덤 초기화 상태이며 학습 전까지 의미를 담고 있지 않음
- 어휘와 임베딩 행렬이 한 몸이라는 사실을 확인할 수 있는 지점임

## 2.6. 특수 토큰

- 모델 동작을 위해 예약된 토큰임
- `<bos>` — 문장 시작이자 디코더의 첫 입력
- `<eos>` — 생성 종료 신호
- `<pad>` — 배치 길이를 맞추는 채움값
- `<unk>` — 표현 불가 토큰 (서브워드에서는 거의 발생하지 않음)
- `<mask>` — 사전학습에서 가려진 토큰 (9~10주차)
- BERT 계열은 `[CLS]`와 `[SEP]`을 사용함

**번역 태스크의 실제 입력**

```
인코더 입력:  <bos> I love cats <eos>
디코더 입력:  <bos> I love cats
디코더 정답:  I love cats <eos>
```

- 디코더 입력과 정답이 한 칸씩 밀려 있음
- teacher forcing이라 부르며 4주차에서 다룸

## 2.7. 패딩과 어텐션 마스크

- 1.2.에서 언급한 가변 길이 문제를 해결하는 단계임
- 배치 내 최대 길이에 맞춰 나머지를 `<pad>`로 채움

```
[ I,   love,  cats,  <pad> ]
[ the, dog,   bit,   him   ]
[ yes, <pad>, <pad>, <pad> ]
```

- 마스크를 함께 전달해 `<pad>` 위치를 계산에서 제외함

```
[1, 1, 1, 0]
[1, 1, 1, 1]
[1, 0, 0, 0]
```

- 마스크를 누락하면 모델이 `<pad>`를 실제 단어로 학습함
- 5주차 Attention, 7주차 Transformer에서 마스킹이 반복 등장함
- 이 단계까지 마치면 정수 텐서가 완성되며, 다음은 임베딩 룩업임 (2주차)
