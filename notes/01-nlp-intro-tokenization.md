# 문장이 텐서가 되기까지

*1주차 — 이미지와 텍스트는 무엇이 다르고, 그 차이를 어떻게 메우는가*

---

이미지를 다뤄본 사람이 텍스트를 처음 만나면 예상과 다른 곳에서 막힌다.

모델 구조가 어려워서가 아니다. ResNet을 이해한 사람에게 Transformer의 residual connection은 낯설지 않다. Multi-head attention도 "여러 커널로 서로 다른 패턴을 뽑는다"는 감각으로 어느 정도 따라갈 수 있다.

막히는 건 훨씬 앞이다. **입력이 대체 뭐냐**는 지점이다.

이미지는 명확하다. `224 × 224 × 3` 텐서. 리사이즈하면 크기가 맞고, 값은 실수이며, 미분도 자연스럽게 정의된다. `model(x)`에 넣기까지 고민할 게 별로 없다.

문장은 그렇지 않다. `"I love cats"`를 어떻게 텐서로 만들 것인가? 리사이즈에 해당하는 연산이 없다. 단어를 반으로 줄일 수는 없으니까.

이번 주는 두 가지를 다룬다. **이미지와 텍스트가 정확히 무엇이 다른지**, 그리고 **그 차이를 메우기 위해 텍스트가 거치는 과정**이 무엇인지.

---

# 1부. 무엇이 다른가

## 연속과 이산

가장 근본적인 차이 하나만 꼽으라면 이것이다.

픽셀 값은 연속 공간에 산다. 130과 131 사이에는 130.5가 있고, 그 값은 의미가 있다. 조금 밝아진 것이다. 값을 조금 흔들면 결과도 조금 변한다. 그래서 gradient가 자연스럽게 흐른다.

토큰 ID는 그렇지 않다. 어휘 사전에서 130번이 `apple`이고 131번이 `zebra`라면, 그 사이에 130.5번은 없다. 두 숫자는 아무 관계도 없다. 사전을 알파벳순으로 정렬했느냐 빈도순으로 정렬했느냐에 따라 완전히 달라지는, 그저 임의의 번호다.

이 차이가 NLP에 CV에는 없는 단계를 하나 더 만든다. **이산 심볼을 연속 벡터로 옮기는 과정**이다. 그게 임베딩이고, 2주차의 주제다.

그리고 임베딩을 하려면 그 전에 정해야 한다. **무엇을 하나의 심볼로 볼 것인가?** 이번 주의 진짜 질문이다.

## 리사이즈가 없다

이미지 배치를 만드는 건 쉽다. 크기가 다르면 리사이즈하거나 크롭하면 된다. 정보가 조금 손실되지만 배치는 만들어진다.

문장은 길이가 제각각인데 줄일 방법이 없다. 5단어짜리와 500단어짜리를 같은 텐서에 담아야 한다.

해법은 나중에 나오지만(패딩과 마스킹), 여기서 기억할 건 이게 **CV에는 존재하지 않는 종류의 문제**라는 점이다.

## 최소 단위의 의미

픽셀 하나는 아무 의미가 없다. `(128, 64, 32)`라는 값 하나만 보고 알 수 있는 건 없다. 의미는 픽셀들이 모여 만드는 패턴에서 나온다. CNN이 하는 일이 바로 그 조립이다.

토큰은 다르다. `cat`이라는 토큰 하나가 이미 의미를 갖는다. 조립이 어느 정도 끝난 상태에서 시작하는 셈이다.

이게 왜 중요하냐면, **무엇을 최소 단위로 삼느냐가 곧 설계 결정**이 되기 때문이다. 픽셀은 주어지지만 토큰은 우리가 정한다.

## 순서가 곧 의미다

CNN은 translation invariance를 얻으려고 애쓴다. 고양이가 왼쪽에 있든 오른쪽에 있든 고양이여야 하니까.

텍스트에서는 정반대다.

```
The dog bit the man
The man bit the dog
```

같은 단어, 같은 개수, 완전히 다른 의미다. 위치 정보를 잃으면 안 된다. 나중에 Transformer가 positional encoding이라는 걸 따로 붙이는 이유가 여기 있다. Self-attention 자체는 순서를 모르기 때문이다.

## 지역성이 약하다

인접한 픽셀은 강하게 연관되어 있다. 그래서 3×3 커널이 통한다.

문장에서는 멀리 떨어진 단어가 강하게 얽힐 수 있다.

```
The keys that I left on the kitchen table this morning are missing
```

`keys`와 `are`는 아홉 단어 떨어져 있지만 수 일치로 묶여 있다. 고정 크기 커널로는 잡기 어렵고, 이게 RNN에서 attention으로, 다시 Transformer로 넘어간 흐름의 배경이다.

---

## 정리하면

| | 이미지 | 텍스트 |
|---|---|---|
| 값 | 연속 | 이산 |
| 크기 | 고정 가능 (리사이즈) | 가변 (패딩 필요) |
| 최소 단위 | 의미 없음 (픽셀) | 의미 있음 (토큰) |
| 순서 | 불변이면 좋음 | 바뀌면 의미가 바뀜 |
| 의존 거리 | 대체로 지역적 | 장거리도 흔함 |

**하지만 CV 지식이 버려지는 건 아니다.** Residual connection과 LayerNorm은 7주차 Transformer 블록의 핵심 구성요소이고, ImageNet pretrain → fine-tune 패러다임은 9주차 사전학습 모델과 정확히 같은 발상이다. 앞부분만 다르고 뒤로 갈수록 익숙해진다.

# 2부. 문장이 텐서가 되기까지

`"I love cats"`가 `model(x)`에 들어가기까지 여섯 단계를 거친다.

```
원문 텍스트
  ↓ ① 정규화
  ↓ ② 사전 분할
  ↓ ③ 토큰화              ← 이번 주의 핵심
토큰 리스트
  ↓ ④ 어휘 매핑
정수 ID
  ↓ ⑤ 특수 토큰 추가
  ↓ ⑥ 패딩 + 마스크
정수 텐서
  ↓   임베딩 룩업          ← 2주차
실수 벡터 → 모델
```

하나씩 보자.

## ① 정규화

유니코드 정규화, 소문자화, 제어문자 정리 같은 것들이다.

사소해 보이지만 결정이 필요하다. 소문자화하면 `Apple`과 `apple`이 같은 토큰이 되어 어휘가 줄지만, 회사와 과일을 구분할 단서를 잃는다. BERT에는 `bert-base-uncased`와 `bert-base-cased`가 따로 있는 이유다. 요즘 모델은 대체로 대소문자를 유지하는 쪽으로 갔다.

## ② 사전 분할

토큰화 전에 텍스트를 대충 잘라두는 단계다. 보통 공백과 구두점 기준이다.

이 단계가 있는 이유는 성능이다. 문장 전체에서 문자쌍 빈도를 세는 것보다, 단어 단위로 나눠놓고 그 안에서 세는 게 훨씬 빠르다. 그리고 서브워드 조각이 단어 경계를 넘어가지 않게 막아준다.

여기서 구현 차이가 생긴다. GPT-2는 공백을 `Ġ`라는 문자로 바꿔서 토큰에 붙이고, T5는 `▁`를 쓴다. 나중에 토크나이저 출력을 보면 이 기호들이 보일 텐데, 단어 시작 표시라고 생각하면 된다.

## ③ 토큰화

핵심 단계다. 무엇을 하나의 단위로 볼 것인가.

### 단어로 자르면

가장 직관적이다. 그리고 곧바로 세 가지 문제에 부딪힌다.

**학습 때 못 본 단어는 사라진다.** 고유명사, 신조어, 오타가 전부 `<unk>` 하나로 뭉개진다. 번역에서 이건 치명적이다. 인명을 틀리는 게 아니라 아예 없었던 것처럼 처리된다.

**어휘가 폭발한다.** 영어만 해도 활용형까지 세면 수십만 개다. V = 200,000에 d = 512면 임베딩 행렬 하나가 1억 파라미터다. 출력층 softmax도 같은 크기다. 모델을 만들기도 전에 예산을 다 쓴다.

**형태론적 관계를 못 배운다.** `run`, `runs`, `running`, `ran`이 서로 무관한 ID가 된다. 사람에게는 당연한 연결이 모델에게는 없고, 희귀한 활용형은 데이터가 부족해 학습되지도 않는다.

### 글자로 자르면

반대 극단이다. 어휘가 100개 남짓으로 줄고 OOV가 사라진다.

대신 시퀀스가 5~10배 길어진다. Transformer에서 attention은 길이의 제곱으로 늘어나므로 치명적이다. 그리고 토큰 하나에 의미가 없어서, 모델이 "글자를 모아 단어를 만드는 법"부터 배워야 한다. 우리가 이미 아는 걸 굳이 다시 학습시키는 셈이다.

### 그래서 서브워드

답은 중간에 있었다.

> **자주 나오는 단어는 통째로, 드문 단어는 조각으로.**

```
"cat"          → ["cat"]
"lowest"       → ["low", "est"]
"tokenization" → ["token", "ization"]
```

한 번의 타협으로 세 문제가 동시에 풀린다. 최악의 경우 글자까지 쪼개면 되니 OOV가 없고, 어휘를 32,000 정도로 고정할 수 있고, `low`와 `lowest`가 조각을 공유하니 형태론적 관계도 어느 정도 잡힌다.

앞으로 12주 동안 볼 모델 — GNMT, Transformer, BART, T5 — 이 **전부 서브워드를 쓴다.** 예외가 없다.

### BPE, 압축 알고리즘에서 온 아이디어

가장 널리 쓰이는 서브워드 알고리즘은 BPE(Byte Pair Encoding)다.

재미있는 건 출신이다. 원래 1994년에 나온 **데이터 압축** 알고리즘이었다. Sennrich와 동료들이 2016년에 기계번역 토큰화에 가져다 쓰면서 표준이 됐다.

동작은 놀랄 만큼 단순하다. 모든 단어를 글자로 분해하고, 가장 자주 인접해 나타나는 문자쌍을 찾아 합치고, 그 규칙을 기록한다. 원하는 어휘 크기가 될 때까지 반복한다. 끝이다. 학습 파라미터도 없고 언어학 지식도 필요 없다. 그냥 센다.

작은 코퍼스로 따라가 보자.

```
low     × 5
lower   × 2
newest  × 6
widest  × 3
```

글자로 펼쳐 인접 쌍을 세면 `(e,s)`가 9번으로 가장 많다. newest에 6번, widest에 3번. 합친다.

그다음은 `(es,t)`가 9번. 합친다. `est`가 생겼다.

계속하면 `(l,o)` 7번, 이어서 `(lo,w)` 7번. `low`가 만들어진다.

어휘에 추가된 순서는 이렇다.

```
es → est → lo → low
```

특별한 지능이 개입하지 않았다. 빈도를 셌을 뿐인데 사람이 봐도 말이 되는 조각이 나왔다.

**그리고 처음 보는 단어를 만났을 때** 진짜 가치가 드러난다.

학습 코퍼스에 `lowest`는 한 번도 없었다. 그런데 기록해둔 규칙을 순서대로 적용하면:

```
l o w e s t
→ (e+s)    l o w es t
→ (es+t)   l o w est
→ (l+o)    lo w est
→ (lo+w)   low est

결과: ["low", "est"]
```

`<unk>`가 나오지 않는다. 그리고 모델은 `low`가 무슨 뜻인지, `est`가 최상급을 뜻한다는 걸 다른 단어들에서 이미 배웠다. 처음 보는 단어의 의미를 추론할 근거가 생긴 것이다.

### 사촌들

BPE만 있는 건 아니다. 어느 회사가 무엇을 쓰는지 알아두면 나중에 헷갈리지 않는다.

**WordPiece**는 빈도 대신 "합쳤을 때 언어 모델 우도가 얼마나 오르는가"로 고른다. Google BERT가 쓰고, 6주차에 볼 GNMT도 이걸 썼다. 단어 중간 조각에 `##`을 붙이는 그 방식이다.

**Unigram LM**은 반대 방향이다. 큰 어휘에서 시작해 손실이 적은 토큰을 제거해 나간다. T5와 mT5가 쓴다.

**SentencePiece**는 알고리즘이 아니라 툴킷이다. 헷갈리기 쉬운 지점이다. 내부에서 BPE나 Unigram을 골라 쓰고, 공백을 `▁`로 바꿔 처리한다. 덕분에 띄어쓰기 규칙이 다른 언어에서도 일관되게 동작한다.

## ④ 어휘 매핑

토큰을 정수로 바꾼다. 그냥 사전 조회다.

```python
["I", "love", "cats"] → [40, 1842, 11875]
```

여기서 어휘 크기 V가 결정된다. 임베딩 행렬이 V × d이므로 **V가 커지면 파라미터가 선형으로 늘어난다.** 앞에서 본 모든 고민의 출발점이 이것이다.

## ⑤ 특수 토큰

모델 동작을 위한 예약 토큰이 붙는다.

`<bos>`는 문장 시작이자 **디코더의 첫 입력**이고, `<eos>`는 생성을 멈추라는 신호다. 이 둘이 없으면 디코더는 어디서 시작해 어디서 끝낼지 모른다. BERT 계열은 `[CLS]`와 `[SEP]`을 쓰고, 사전학습에는 `<mask>`가 등장한다.

번역 태스크의 실제 입력은 이런 모양이 된다.

```
인코더 입력:  <bos> I love cats <eos>
디코더 입력:  <bos> 私は 猫が 好きです
디코더 정답:  私は 猫が 好きです <eos>
```

디코더 입력과 정답이 한 칸씩 밀려 있다. teacher forcing이라고 부르는데, 4주차에 제대로 다룬다. 지금은 "이런 게 있다" 정도면 충분하다.

## ⑥ 패딩과 마스크

1부에서 미뤄둔 문제로 돌아왔다. 길이가 다른 문장을 하나의 텐서에 담아야 한다.

배치 안에서 가장 긴 문장에 맞춰 나머지를 `<pad>`로 채운다.

```
[ I,   love, cats, <pad> ]
[ the, dog,  bit,  him   ]
[ yes, <pad>,<pad>,<pad> ]
```

그리고 **반드시** 마스크를 함께 넘겨 `<pad>` 위치를 계산에서 제외해야 한다.

```
[1, 1, 1, 0]
[1, 1, 1, 1]
[1, 0, 0, 0]
```

이걸 빼먹으면 모델이 `<pad>`를 진짜 단어로 학습한다. 5주차 Attention과 7주차 Transformer에서 마스킹이 계속 나오니 개념은 여기서 확실히 잡아두는 게 좋다.

이제 정수 텐서가 완성됐다. 다음은 임베딩 룩업인데, 그건 2주차 이야기다.

## 빅테크는 같은 문장을 어떻게 자르는가

같은 문장을 여러 회사의 토크나이저에 넣어보면 설계 차이가 그대로 드러난다.

| 토크나이저 | 만든 곳 | 알고리즘 |
|---|---|---|
| `gpt2` | OpenAI | BPE |
| `bert-base-uncased` | Google | WordPiece |
| `t5-small` | Google | Unigram (SentencePiece) |
| `facebook/bart-base` | Meta | BPE |
| `xlm-roberta-base` | Meta | Unigram (SentencePiece) |

같은 문장이 토크나이저마다 다른 개수로 쪼개지고, 공백 표시도 `Ġ`, `##`, `▁`로 제각각이다. 표준이 하나가 아니라는 걸 눈으로 보는 게 목적이다.

특히 코드나 전문 용어를 넣어보면 차이가 커진다. 학습 데이터에 무엇이 많았는지가 그대로 드러나기 때문이다.

## 어휘에 단어를 추가하기

실무에서 가장 자주 마주치는 상황이다.

특정 도메인 용어가 계속 잘게 쪼개진다고 하자. 한 단어여야 할 게 매번 5토큰을 잡아먹으면 시퀀스가 길어지고, 모델은 그 개념을 하나의 단위로 배우기 어렵다.

해법은 어휘에 직접 추가하는 것이다.

```python
tokenizer.add_tokens(["myoglobin", "hemoglobin"])
```

한 줄이지만 결과가 따라온다. **어휘 크기가 늘어났으므로 임베딩 행렬도 커져야 한다.**

```python
model.resize_token_embeddings(len(tokenizer))
```

이걸 빼먹으면 새 토큰 ID가 임베딩 행렬 범위를 넘어가 그대로 에러가 난다. 그리고 새로 생긴 임베딩 행은 **랜덤 초기화 상태**다. 학습을 거치기 전까지는 아무 의미도 담고 있지 않다.

여기서 얻는 감각이 중요하다. 어휘와 임베딩 행렬은 한 몸이다. 앞에서 "V가 커지면 파라미터가 늘어난다"고 한 말이 추상적인 설명이 아니라 실제로 만져지는 것이라는 걸 확인하게 된다.

# 발표할 때

90분이면 이 정도 배분이 무리 없다.

커리큘럼 전체 지도 10분, **1부 이미지와의 차이 20분**, 2부 파이프라인 개요 10분, **토큰화와 BPE 25분**, 특수 토큰과 마스킹 10분, 실습 데모 15분.

시간이 부족하면 사촌 알고리즘 비교를 줄인다. 반대로 절대 줄이면 안 되는 건 이산성 설명, BPE 예제, 마스킹 세 가지다. 이후 주차가 전부 여기 기댄다.

발표가 끝났을 때 청중이 이 질문들에 답할 수 있으면 성공이다.

- 이미지와 텍스트의 가장 근본적인 차이는?
- 텍스트가 모델에 들어가기까지 거치는 단계는?
- 단어 단위 토큰화의 문제 세 가지는?
- 서브워드가 OOV를 없애는 원리는?
- 어휘 크기를 키우면 무엇이 좋아지고 무엇이 나빠지는가?
- `<pad>`를 마스킹하지 않으면 무슨 일이 일어나는가?
