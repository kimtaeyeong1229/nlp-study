# 픽셀에는 없고 단어에는 있는 것

*1주차 — NLP 입문과 토큰화, 그리고 서브워드*

---

이미지를 다뤄본 사람이 텍스트를 처음 만나면 이상한 지점에서 막힌다.

모델 구조가 어려워서가 아니다. ResNet을 이해한 사람에게 Transformer의 residual connection은 낯설지 않다. Multi-head attention도 "여러 커널로 서로 다른 패턴을 뽑는다"는 감각으로 어느 정도 따라갈 수 있다.

막히는 건 훨씬 앞이다. **입력이 대체 뭐냐**는 지점이다.

이미지는 명확하다. 224×224×3 텐서. 리사이즈하면 크기가 맞고, 픽셀 값 130과 131은 거의 같은 값이며, 미분도 자연스럽게 정의된다.

문장은 그렇지 않다. "나는 밥을 먹었다"를 어떻게 텐서로 만들 것인가? 리사이즈에 해당하는 연산이 없다. 단어를 반으로 줄일 수는 없다.

이 글은 그 간극을 메우는 이야기다.

---

## 224로 리사이즈할 수 없는 것들

CV와 NLP의 차이를 한 줄로 줄이면 이렇다. **하나는 연속이고 하나는 이산이다.**

픽셀 값은 연속 공간에 산다. 130과 131 사이에는 130.5가 있고, 그 값은 의미가 있다. 조금 밝아진 것이다.

토큰 ID는 그렇지 않다. 어휘 사전에서 130번이 "사과"이고 131번이 "사랑"이라면, 그 사이에 130.5번은 없다. 두 숫자는 아무 관계도 없다. 사전을 알파벳순으로 정렬했느냐 빈도순으로 정렬했느냐에 따라 완전히 달라지는, 그저 임의의 번호다.

그래서 NLP에는 CV에 없는 단계가 하나 더 있다. **이산 심볼을 연속 벡터로 옮기는 과정.** 그게 임베딩이고, 2주차의 주제다.

이번 주는 그 직전 질문을 다룬다. 임베딩을 하려면 먼저 정해야 한다. **무엇을 하나의 심볼로 볼 것인가?**

차이는 몇 가지 더 있다. 문장은 길이가 제각각이고, 픽셀 하나는 아무 의미가 없지만 토큰 하나는 이미 의미 단위다. 그리고 결정적으로, CNN이 그렇게 공들여 얻어낸 translation invariance가 여기서는 오히려 독이다. "개가 사람을 물다"와 "사람이 개를 물다"는 완전히 다른 문장이니까.

---

## 그래서 무엇을 하나로 볼 것인가

파이프라인은 단순하다.

```
원문 → 정규화 → 토큰화 → 어휘 매핑 → 임베딩 → 모델
```

정규화는 사소해 보이지만 한국어에서는 그렇지 않다. 같은 "각"이 조합형과 완성형 두 가지 유니코드로 존재할 수 있어서, NFC 정규화를 빼먹으면 눈에 똑같아 보이는 두 글자가 다른 토큰이 된다.

어휘 매핑은 그냥 사전 조회다.

```python
vocab = {"<pad>": 0, "<unk>": 1, "나는": 2, "밥을": 3, "먹었다": 4}
"나는 밥을 먹었다" → [2, 3, 4]
```

여기서 중요한 건 어휘 크기 V다. 임베딩 행렬이 V × d이므로, **V가 커지면 파라미터가 선형으로 늘어난다.** 출력층 softmax도 V 크기다. 이 사실이 앞으로 나올 모든 고민의 출발점이다.

그리고 그 앞에 토큰화가 있다. 이번 주의 진짜 주제다.

---

## 단어로 자르면 생기는 일

가장 먼저 떠오르는 방법은 공백으로 자르는 것이다. 직관적이고, 토큰 하나하나가 의미를 갖는다.

문제는 곧바로 드러난다.

**학습 때 못 본 단어는 전부 사라진다.** 고유명사, 신조어, 오타가 모두 `<unk>`라는 하나의 토큰으로 뭉개진다. 번역에서 이건 치명적이다. 인명 하나 틀리는 게 아니라, 아예 존재하지 않았던 것처럼 처리된다.

**어휘가 폭발한다.** 영어만 해도 활용형까지 세면 수십만 개다. V = 200,000에 d = 512면 임베딩 행렬 하나가 1억 파라미터다. 모델을 만들기도 전에 예산을 다 쓴다.

**형태론적 관계를 못 배운다.** `run`, `runs`, `running`, `ran`이 서로 무관한 ID가 된다. 사람에게는 당연한 연결이 모델에게는 없다. 희귀한 활용형은 데이터가 부족해서 제대로 학습되지도 않는다.

그리고 한국어에서는 이 모든 게 훨씬 심각해진다.

```
먹다, 먹는다, 먹었다, 먹겠다, 먹었었다, 먹으니까, 먹어서, 먹더라도, ...
```

어간은 `먹` 하나인데 어미 조합으로 표면형이 사실상 무한히 늘어난다. 교착어의 특성이다. 공백으로 자르는 순간 이 관계는 완전히 사라진다.

그래서 한국어 NLP는 오랫동안 형태소 분석기에 의존했다. 언어학적 지식을 넣어서 `먹 + 었다`로 쪼개는 방식이다. 나쁘지 않은 접근이었고, 지금도 유효한 상황이 있다. 하지만 이 이야기의 결말은 다른 쪽이다.

---

## 그럼 글자로 자르면?

반대 극단으로 가보자. 한 글자씩 자르면 어휘는 아주 작아진다. 영어는 100개 남짓, 한글도 음절 기준 11,172개다. OOV는 원천적으로 사라진다. 어떤 단어든 글자로는 표현할 수 있으니까.

대신 시퀀스가 5~10배 길어진다. RNN에서는 학습이 견디기 힘들 만큼 느려지고, Transformer에서는 attention이 길이의 제곱으로 늘어나므로 더 나쁘다.

더 근본적인 문제는 토큰 하나에 의미가 없다는 것이다. 모델이 "글자를 모아 단어를 만드는 법"부터 배워야 한다. 우리가 이미 아는 것을 굳이 다시 학습시키는 셈이다.

두 극단 모두 답이 아니다.

---

## 타협점, 서브워드

답은 중간에 있었다. 한 문장으로 요약하면 이렇다.

> **자주 나오는 단어는 통째로, 드문 단어는 조각으로.**

```
"lowest"       → ["low", "est"]
"tokenization" → ["token", "ization"]
"먹었다"        → ["먹", "었다"]
```

이 한 번의 타협으로 세 문제가 동시에 풀린다. 최악의 경우 글자 단위까지 쪼개면 되니 OOV가 없고, 어휘 크기를 32,000 정도로 고정할 수 있고, `low`와 `lowest`가 조각을 공유하므로 형태론적 관계도 어느 정도 잡힌다.

앞으로 12주 동안 볼 모델 — GNMT, Transformer, BART, T5 — 이 **전부 서브워드를 쓴다.** 예외가 없다.

---

## 압축 알고리즘에서 온 아이디어

가장 널리 쓰이는 서브워드 알고리즘은 BPE(Byte Pair Encoding)다.

재미있는 건 출신이다. 원래 1994년에 나온 **데이터 압축** 알고리즘이었다. Sennrich와 동료들이 2016년에 이걸 기계번역 토큰화에 가져다 쓰면서 표준이 됐다.

동작은 놀랄 만큼 단순하다.

1. 모든 단어를 글자 단위로 분해한다
2. 가장 자주 인접해 나타나는 문자쌍을 찾는다
3. 그 쌍을 하나의 토큰으로 합치고, 규칙을 기록한다
4. 원하는 어휘 크기가 될 때까지 반복한다

끝이다. 학습 가능한 파라미터도 없고, 언어학 지식도 필요 없다. 그냥 센다.

### 직접 세어보기

작은 코퍼스로 따라가 보자.

```
low     × 5
lower   × 2
newest  × 6
widest  × 3
```

글자로 펼치고 인접 쌍을 세면, `(e,s)`가 9번으로 가장 많다. newest에 6번, widest에 3번. 합친다.

그다음은 `(es,t)`가 9번. 합친다. 이제 `est`라는 토큰이 생겼다.

계속하면 `(l,o)` 7번, 이어서 `(lo,w)` 7번. `low`가 만들어진다.

다섯 번의 병합 후 어휘에 추가된 순서는 이렇다.

```
es → est → lo → low
```

특별한 지능이 개입하지 않았다. 그냥 빈도를 셌을 뿐인데 `low`와 `est`라는, 사람이 봐도 말이 되는 조각이 나왔다.

### 그리고 처음 보는 단어를 만났을 때

여기서 진짜 마법이 일어난다.

학습 코퍼스에 `lowest`는 **한 번도 없었다.** 그런데 기록해둔 병합 규칙을 순서대로 적용하면:

```
l o w e s t
→ (e+s)    l o w es t
→ (es+t)   l o w est
→ (l+o)    lo w est
→ (lo+w)   low est

결과: ["low", "est"]
```

`<unk>`가 나오지 않는다. 그리고 모델은 이미 `low`가 무슨 뜻인지, `est`가 최상급을 뜻한다는 걸 다른 단어들에서 배웠다. 처음 보는 단어의 의미를 추론할 근거가 생긴 것이다.

발표에서 이 부분은 시간을 넉넉히 쓰는 게 좋다. 슬라이드에서 병합 과정을 한 단계씩 보여주면 이해도가 확 올라간다.

## 사촌들

BPE만 있는 건 아니다. 이름만 알아두면 충분하지만, 어느 모델이 무엇을 쓰는지는 알아두면 나중에 헷갈리지 않는다.

**WordPiece**는 빈도 대신 "합쳤을 때 언어 모델 우도가 얼마나 오르는가"로 고른다. BERT가 쓰고, 6주차에 볼 GNMT도 이걸 썼다.

**Unigram LM**은 반대 방향이다. 큰 어휘에서 시작해 손실이 적은 토큰을 제거해 나간다. T5와 mT5가 쓴다.

**SentencePiece**는 알고리즘이 아니라 툴킷이다. 이걸 헷갈리는 사람이 많다. 내부에서 BPE나 Unigram을 골라 쓰고, 공백을 `▁`라는 특수문자로 바꿔 처리한다. 덕분에 띄어쓰기가 없는 중국어·일본어나 띄어쓰기가 불안정한 한국어에서도 일관되게 동작한다. mBART와 mT5가 이걸 쓴다.

---

## 그리고 남은 잡일

서브워드 토큰 말고도 예약된 토큰이 몇 개 필요하다. `<pad>`, `<unk>`, `<bos>`, `<eos>`, `<mask>`. 이름만 봐도 역할이 짐작되는 것들이다.

이 중 `<pad>`가 CV에는 없는 골칫거리를 만든다.

이미지는 리사이즈로 크기를 맞추지만 문장은 그럴 수 없다. 그래서 배치 안에서 가장 긴 문장에 맞춰 나머지를 `<pad>`로 채운다.

```
[나는,  밥을,   먹었다, <pad>]
[오늘,  날씨가, 정말,   좋다 ]
[응,    <pad>,  <pad>,  <pad>]
```

그리고 반드시 마스크를 함께 넘겨서 `<pad>` 위치를 계산에서 제외해야 한다.

```
[1, 1, 1, 0]
[1, 1, 1, 1]
[1, 0, 0, 0]
```

이걸 빼먹으면 모델이 `<pad>`를 진짜 단어로 학습한다. 5주차 Attention과 7주차 Transformer에서 마스킹이 계속 나오므로, 개념은 지금 확실히 잡아두는 게 좋다.

## 실습

네 가지를 직접 확인한다. 코드와 실행 결과는 [`notebooks/01_tokenization.ipynb`](../notebooks/01_tokenization.ipynb)에 있다.

**BPE를 직접 학습시키면** 위에서 손으로 계산한 병합 순서(`es → est → lo → low`)가 그대로 재현된다. 그리고 학습에 없던 `lowest`가 `['low', 'est']`로 쪼개지는 것도 확인할 수 있다.

> 노트북 결과에는 `est</w>`가 아니라 `est`로 나온다. Sennrich 원 논문은 단어 끝에 `</w>`를 붙이지만 `tokenizers` 라이브러리 기본값은 붙이지 않는다. 병합 순서와 최종 분절은 같다. 단어 경계 표시 방식이 구현마다 다르다는 것(`</w>`, `##`, `▁`)만 짚어주면 된다.

**어휘 크기를 바꿔보면** 트레이드오프가 눈에 보인다. 80 → 150 → 300으로 키우면 토큰 수가 25 → 22 → 17로 줄어든다. 그런데 1000으로 더 키워도 17에서 멈춘다. 코퍼스가 작아서 더 합칠 게 없는 것이다.

더 흥미로운 건 이 부분이다. 어휘를 아무리 키워도 코퍼스에 없던 `multilingual`은 9조각 그대로다. **BPE는 본 것만 합친다.** 도메인이 다른 텍스트에서 토큰이 급증하는 이유가 여기 있다.

**mBERT로 같은 의미의 문장을 잘라보면** 영어 8토큰, 한국어 16토큰이 나온다. 정확히 두 배다. `자연어처리`는 `자 / ##연 / ##어 / ##처 / ##리` 다섯 조각으로 부서진다.

이게 왜 문제인가? 컨텍스트 길이 제한은 언어와 무관하게 같기 때문이다. 512토큰 제한에서 한국어는 영어의 절반밖에 담지 못한다. API 과금도 토큰 단위다. 이 문제는 11~12주차 다국어 모델에서 다시 나온다.

**형태소 분석기와 비교하면** 대비가 선명해진다. Okt는 `자연어처리`를 `자연어 + 처리`로 정확히 나누고 품사까지 붙여준다. 언어학적으로 훨씬 정확하다.

그러면 왜 요즘 모델은 형태소 분석기를 쓰지 않을까. 발표에서 반드시 나올 질문이고, 답은 세 가지다. 언어마다 분석기를 따로 만들어야 하고, 분석기의 오류가 모델로 그대로 전파되고, 신조어와 오타에 취약하다.

**확장성이 정확도를 이긴 사례다.** 이 관점은 앞으로 12주 내내 반복해서 등장한다.

2주차에서는 그 번호에 의미를 입힌다. Word2Vec으로 단어를 벡터 공간에 배치하고, 그 벡터들의 나열을 RNN과 LSTM으로 처리한다.
