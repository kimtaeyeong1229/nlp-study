딥러닝 모델이 받는 입력은 결국 실수로 채워진 텐서입니다. 그런데 우리가 LLM에 무언가를 물어볼 때 넣는 것은 그냥 평소에 쓰는 말입니다. 텐서는커녕 숫자 하나 없는 문장인데, 모델은 이것을 어떻게 읽는 걸까요? 이번 글에서는 GPT-2를 기준으로 `"Hello World!"`가 모델이 읽을 수 있는 텐서가 되기까지를 살펴보겠습니다.

# 목차

1. **토큰화 (Tokenization)**
2. **정수 인코딩 (Encoding)**
3. **특수 토큰과 패딩 (Batching)**
4. **임베딩 룩업 (Embedding)**

# **1. 토큰화 (Tokenization)**

모델은 미리 만들어둔 단어장에 있는 조각으로만 문장을 표현합니다. 이 단어장을 어휘(vocabulary)라고 부릅니다. 어휘를 단어 단위로 채우면 학습 때 못 본 단어를 담을 자리가 없어, 전부 ``<unk>`(unknown)`라는 토큰 하나로 대체됩니다. 

고유명사든 오타든 구분이 사라지고, 활용형까지 담느라 어휘도 수십만 개로 불어납니다. 글자 단위로 채우면 어휘는 알파벳 수십 개로 끝나지만, 이번엔 ``Hello`` 한 단어가 ``H e l l o`` 다섯 토큰이 됩니다. 글자 하나에는 뜻이 없으니 모델이 글자를 단어로 조합하는 일부터 배워야 합니다. 최악의 경우 글자까지 내려가면 되므로 모르는 단어가 원칙적으로 사라지고, 어휘 크기도 원하는 값에 고정할 수 있습니다.

이를 해결하기 위해 서브워드(subword) 기법을 사용합니다. 자주 쓰이는 단어는 통째로 한 토큰에 담고, 드문 단어만 여러 조각으로 쪼갭니다. 이를 통해 어휘 크기를 원하는 값으로 정할 수 있고, GPT-2는 이렇게 어휘를 50,257개로 맞췄습니다.

```jsx
"Hello"        → ["Hello"]
"lowest"       → ["low", "est"]
"tokenization" → ["token", "ization"]
```

GPT-2는 서브워드 기법 중에서 BPE(Byte Pair Encoding) 알고리즘을 사용합니다. 모든 단어를 글자로 분해한 뒤 가장 자주 붙어 나오는 문자쌍을 찾아 합치는 일을 반복하고, 그 규칙을 순서대로 기록합니다.

```jsx
low × 5    lower × 2    newest × 6    widest × 3

1. 빈도가 높은 'low'와 'est'를 어휘로 채택
2. 이를 통해 어휘에 없는 'lowest'를 [low] + [est]'로 표현 가능
```

결론적으로 BPE 알고리즘을 통해서 `<unk>`가 나오는 것을 방지하며, 어휘에 없는 단어라도 어휘에 있는 조각을 이어 붙여 표현할 수 있는 것입니다.

# 2. 정수 인코딩 (Encoding)

어휘가 정해졌으니 조각마다 번호를 붙입니다. 단어장의 몇 번째 항목인지 적어두는 것뿐입니다. 

```jsx
"Hello World!"  →  ['Hello', 'ĠWorld', '!']  →  [4546, 2159, 0]
```

토큰에 붙은 `Ġ`는 앞에 띄어쓰기가 있었다는 표시입니다. 나중에 토큰을 다시 문장으로 되돌려야 하므로 공백도 정보로 남겨둡니다.  

이 번호는 사물함 번호와 같습니다. 4546번이 2159번보다 크다고 해서 뜻이 있는 게 아닙니다. 그냥 자리일 뿐이라 어휘를 다른 순서로 정렬하면 번호도 전부 바뀝니다. 번호끼리 더하거나 비교해봐야 아무것도 나오지 않습니다.

# 3. **특수 토큰과 패딩 (Batching)**

문장 자체에는 없지만 모델을 돌리려면 필요한 토큰이 있습니다.

- `<bos>` (beginning of sequence): 문장의 시작
- `<eos>` (end of sequence): 문장의 끝
- `<unk>` (unknown): 어휘에 없는 단어의 대타
- `<pad>` (padding): 배치 길이를 맞추는 채움값

지금까지의 토큰화·번호 매기기는 전부 토크나이저(tokenizer)라는 하나의 도구가 처리합니다. GPT-2의 토크나이저를 열어보면 이렇습니다.

```jsx
bos_token  = '<|endoftext|>'   id = 50256
eos_token  = '<|endoftext|>'   id = 50256
unk_token  = '<|endoftext|>'   id = 50256
pad_token  = None
```

넷 중 셋이 같은 토큰 하나로 통일되어 있고, 채움용 토큰은 아예 없습니다. GPT-2는 문서를 죽 이어붙여 학습하는 모델이라, 문장 시작·끝·모르는 단어를 구분할 필요 없이 "여기서 문서가 끊긴다"는 신호 하나면 충분하기 때문입니다.

GPT는 다음 토큰을 하나씩 예측해 문장을 만드는데, 여기에는 종료 지점이 없습니다. 그래서 `<|endoftext|>`가 나오면 멈추도록 종료 조건을 걸어둡니다. 토크나이저가 자동으로 붙여주지는 않아서 직접 넣습니다.

```jsx
"Hello World!"                  →  [4546, 2159, 0]
"Hello World!<|endoftext|>"     →  [4546, 2159, 0, 50256]
```

이제 길이를 맞출 차례입니다. 문장 길이는 제각각인데 텐서는 직사각형이어야 합니다. 배치에서 가장 긴 문장에 맞춰 나머지를 `<pad>`로 채우고, 어느 자리가 채움값인지 알려주는 마스크를 함께 넘깁니다.

```jsx
[ Hello, World, !,     <pad> ]        [1, 1, 1, 0]
[ The,   dog,   bit,   him   ]        [1, 1, 1, 1]
[ Yes,   <pad>, <pad>, <pad> ]        [1, 0, 0, 0]
```

마스크가 필요한 이유는 attention의 계산 방식 때문입니다. attention은 모든 위치가 모든 위치를 한 번에 참조하므로, 마스크가 없으면 뜻 없는 `<pad>`까지 계산에 섞여 들어갑니다. 마스크가 0인 자리의 점수를 softmax 직전에 음의 무한대로 바꾸면 가중치가 정확히 0이 되어, `<pad>`가 없었던 것처럼 처리됩니다.

여기까지 오면 손에 쥔 것은 두 개의 텐서입니다. 길이를 맞춘 토큰 번호(`input_ids`)와, 어디까지가 진짜인지 표시한 어텐션 마스크(`attention_mask`)입니다.

# 4. **임베딩 룩업 (Embedding)**

4546과 2159는 여전히 사물함 번호일 뿐입니다. 마지막 단계는 이 번호로 실제 벡터를 꺼내오는 것입니다.  

임베딩 행렬은 어휘 개수(`V`)만큼 행이 있고, 각 행에 `d`개의 숫자가 들어 있는 표입니다. 번호가 곧 행 번호라 룩업은 그 행을 꺼내는 인덱싱 한 번으로 끝납니다. GPT-2는 `V = 50,257`, `d = 768`이라 이 표 하나가 38.6M 파라미터입니다.

```jsx
[4546, 2159, 0]  →  (3, 768)

4546번 행  [ 0.021, -0.114,  0.087, ... ]   ← "Hello"
2159번 행  [-0.052,  0.203, -0.011, ... ]   ← " World"
   0번 행  [ 0.134,  0.008, -0.076, ... ]   ← "!"
```

이제 번호가 아니라 실수 벡터입니다. 사물함 번호는 더하거나 빼도 의미가 없었지만, 이 벡터는 더하고 빼고 미분할 수 있습니다. 배치까지 포함하면 최종 입력은 `(batch, seq_len, d)` 모양이 됩니다. 

어휘는 빈도를 세어 한 번 고정되지만, 표의 숫자는 랜덤으로 시작해 학습을 거치며 채워집니다. 그래서 앞의 세 단계와 달리 이 표만은 옵티마이저가 갱신하는 학습 대상입니다. 따로 학습되는 게 아니라 모델의 다른 레이어들과 같은 역전파로 함께 갱신되는, 모델 파라미터의 일부입니다.

# 마무리

GPT-2가 `"Hello World!"`를 받아들이는 과정을 한 줄로 줄이면 이렇습니다.

1. 문장을 조각으로 쪼개고
2. 번호를 매기고
3. 형식을 맞추고
4. 그 번호로 표에서 벡터를 꺼내옵니다

세부 방식은 모델마다 다르지만, 이 네 단계는 대부분 동일하게 거칩니다.
